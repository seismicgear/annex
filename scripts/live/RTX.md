# Real RTX acceptance extension

`rtx.mjs` exports `runRtxAcceptance({ hostFounder, vmFounder, policyHost, policyVm, record, readStoredBundle, setPeerOnline, restartPeer, readStoredOutboxEnvelope })`. The parent federation harness owns starting both servers, fresh databases, real founder registration, peer trust anchors, signed federation agreements and teardown. This module must run only after both peers are ready and before agreement severing. Importing the file is not execution evidence.

`hostFounder` and `vmFounder` are the real identities returned by `protocol.mjs:register`. The policy values are their actual operator HTTP readbacks. `record(action, publicDetails)` receives safe evidence metadata. The optional `readStoredBundle(serverUrl, bundleId)` callback must perform a read-only lookup of the actual `rtx_bundles` row and return that single row or null. It may be synchronous or asynchronous. The extension accepts the real database column names `domain_tags_json`, `caveats_json`, `created_at_ms`, and `provenance_json`, and compares their normalized wire fields. No database writes are performed by the extension.

The assertions cover:

- Four genuine role-2 registrations, membership proofs and authenticated aligned VRP handshakes with fresh Ed25519 signing keys; actual profile and subscription readbacks. Founder-only governance is denied to these agents.
- Windows-to-Ubuntu and Ubuntu-to-Windows signed RTX delivery through independent live WebSockets, alongside local delivery. Every field is compared, independent Node crypto verifies the author signature, actual remote provenance is checked, and founder governance confirms persistence. When the callback is provided, stored bundle bytes on both nodes are independently compared too.
- Canonical author signature binds UTF-8 byte lengths, vectors, null/present reasoning and all content fields. Individual mutations return401; source impersonation/server mismatch return403/400; refused bundles create neither stored bundles nor governance rows. A duplicate genuine publication returns409 with no repeated delivery. Rehandshake omitting the advertised key cannot remove signature enforcement.
- Actual subscription domain changes block both local and federated delivery while positive control recipients receive the same bundles. `accept_federated=false` blocks remote transfer while local transfer still works. Restoring the subscription delivers fresh positive markers without replaying prohibited messages. Negative observations require a continuously connected recipient and no persisted delivery record.
- A genuine sender rehandshake changes its redacted-topic contract. Signed bundles carrying that topic in tags, summary, reasoning or caveats return403; a subsequent actual handshake removing the restriction permits transfer.
- A separate known, non-sensitive reasoning sample verifies `ReflectionSummariesOnly`: local and remote delivered/stored reasoning is null, source governance records stripping, and remote origin attestation preserves the original reasoning commitment. The original author signature is verified before rewriting; the stripped body is explicitly **not** claimed to retain a valid author signature over the modified bytes.
- Actual unsubscribe, GET absence, second DELETE404, no delivery, resubscribe and fresh delivery. Founder governance totals, scope breakdown, source filter and pagination reflect actual transferred bundles. All four subscriptions are removed and read back absent at success.

Accepted `handshakeRef` is read from the real handshake report and independently checked against the agent profile. Validly signed invented, another-author, and stale references are rejected without persistence. No request digest is substituted for a ledger reference.

The lane explicitly enables `allow_full_knowledge` through both founders' real policy API, re-handshakes all agents, and verifies full signed reasoning, delivery and stored bytes in both directions. It restores each original policy in a `finally` block and proves subsequent summary-only stripping again.

Optional lifecycle callbacks must operate on the actual test processes: `setPeerOnline(serverUrl, online)` stops/starts the same server with the same persisted state; `restartPeer(serverUrl)` restarts it and returns after health is ready. The lane stops Ubuntu, publishes a controlled reasoning bundle from Windows, observes the actual terminal failed outbox row, restarts Windows, verifies that row survives, restores Ubuntu, reconnects every agent, and uses the real operator retry endpoint. It proves remote delivery exactly once and confirms delivered rows cannot be retried through that operator endpoint.

`readStoredOutboxEnvelope(serverUrl, rowId)` must read and decrypt the actual persisted envelope without mutation or logging key material. The lane replays those exact signed bytes to the real receiver, expects zero additional deliveries and unchanged audit count, then mutates tags and caveats in the captured scope-stripped v2 envelope and verifies origin-authentication rejection. A subsequent actual delivery is the ordering barrier before checking no duplicated WebSocket frame. The parent owns secret loading; this module records no auth, key or envelope contents.

The returned `durableRecovery` and `authenticatedRetry` flags remain false unless their callbacks ran every assertion. This extension does not claim partial/conflicting alignment, more than one federation hop, desktop UI, or model-generated reasoning.

The definitions were syntax-checked only by their author. A real `federation.mjs` invocation and its source-bound receipts are required for acceptance. Authentication tokens, identity seeds and private signing keys never enter the record callback.

# Encrypted attachment live lane

Definitions are not execution evidence. The initial actual run reached the first successful upload, then failed because Chromium did not expose Blob multipart bytes to Playwright. It did not claim a passing upload proof. The revised lane observes actual bytes through a passive loopback forwarder and still requires full execution. Use a fresh, root-created native server session whose copied client contains the signed encryption and encrypted attachment UI. Run from `client` after the shared browser lane is released:

```powershell
$env:ANNEX_LIVE_URL = 'http://127.0.0.1:3000'
$env:ANNEX_ATTACHMENT_SESSION = 'C:\absolute\work\session-<fresh-name>.json'
$env:ANNEX_ATTACHMENT_PROXY_PORT = '13022' # Must be unused; default is 13022.
npx playwright test -c e2e/live/encrypted-attachments.playwright.config.ts
```

The record must identify that exact backend URL, captured binary hash, and isolated `work/sessions` data directory. The configuration retains this backend URL as `ANNEX_ATTACHMENT_BACKEND_URL` and gives all browser actors the fresh proxy origin. Do not point the session record at the proxy or alter the record. Clear an explicitly inherited `ANNEX_ATTACHMENT_BACKEND_URL` before changing backend sessions. The helper opens SQLite read-only. No database rows, identities, certificates, keys, API results, or application stores are seeded or replaced.

The test owns and closes the proxy. It binds only `127.0.0.1`; HTTP request and response bodies stream through unchanged, and WebSocket upgrades use an actual TCP pipe. Only encrypted-upload multipart bodies are observed, with limits of 64 MiB per body, 128 MiB total and 256 uploads. These ciphertext bytes remain in memory and are cleared on close. Identity proofs, authorization headers, private descriptors and downloaded plaintext are not captured. A bound violation or missing evidence fails explicitly rather than substituting data. Public receipts distinguish the browser origin from the captured backend origin and contain observed byte counts, opaque UUIDs and hashes.

The single serial test registers three actual browser identities and later links a fourth context using the shipped transfer UI. It exercises signed channel encryption and explicit peer trust; all five image privacy fixtures (JPEG, PNG/APNG, GIF, still WebP and animated WebP); an actual browser-encoded WebM; a private text file; all three preview cancellation categories; real upload interruption and retry; cancellation during transfer and after server commit while the acknowledgement is still throttled; local read Retry; persistence/reload; retained attachment edit; nonmember, former-member, wrong-device and removed-device access; fresh message/attachment deletion within the real 60-second author window; and channel deletion for older history.

For successful uploads, actual multipart ciphertext, encrypted socket content, authenticated history, SQLite associations, at-rest message bytes, stored file bytes and a second browser's downloaded plaintext are correlated. Image expected digests come from the independent decoded-cleaned fixture manifest, never from the product sanitizer. Video is decoded by the peer and must produce actual frames. Private transfer codes, client keys, descriptors and bearer grants are never attached to reports. The receipt contains public identifiers, hashes, bounded counts and the exact captured binary hash.

Real TCP interruption, withholding an actual response, and Chromium URL transport blocking create error conditions; no request is fulfilled with a test response. For interruption and cancellation, the upload UUID comes from the actual multipart prefix received by the proxy, not a crypto hook or generated fixture. Cancel-after-commit requires actual ready SQLite state while the browser still displays Uploading, then immediate durable cleanup; orphan TTL is not accepted as explicit cancellation. The proxy forwards exactly 8192 actual multipart bytes before holding the remaining body for the interrupted-send and UI-cancel cases; its cut destroys real sockets. Lost acknowledgement pauses the actual upstream response after the real server completes the upload; it never invents an HTTP status or response body.

Local/origin Retry, prepared-ID encrypted cancellation and the durable pre-finalization cancellation reservation are implemented and component-qualified in the captured candidate. This lane must still prove their combined actual browser behavior. Physical camera input, federated cross-host attachment transfer, and installed native file-picker behavior are separate acceptance boundaries.
